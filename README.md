# «Угадай, про кого этот факт»

Realtime-веб-квиз: ведущий управляет вопросами и таймером, участники отвечают с разных устройств, а после раскрытия голоса группируются по вариантам.

## Готово

- изумрудная адаптивная тема и CSS 3D-иллюстрация;
- 10 вопросов, зафиксированных в проекте;
- редактор вопросов: 4–10 вариантов, правильный ответ, время 5–300 секунд, порядок и удаление;
- безопасная Supabase-схема с RPC-only доступом;
- создание комнаты с шестизначным кодом и секретной ссылкой ведущего;
- вход и восстановление участника по room-scoped секрету;
- Realtime-сигналы с повторным чтением авторизованного snapshot;
- серверные запуск, пауза, продолжение, reveal, переход и завершение;
- один ответ участника на вопрос и серверная проверка дедлайна;
- правильный ответ и чужие голоса скрыты от игрока до reveal;
- группировка реальных голосов по вариантам;
- состояния настройки, загрузки, ожидания, ошибки и завершения.

До создания проекта Supabase сетевые маршруты показывают инструкцию настройки. Старые демонстрационные комнаты вроде `EMERALD42` больше не являются настоящими комнатами.

## Технологии

- Next.js 16 / React 19 / TypeScript
- Zod
- Supabase Postgres, RPC и Realtime
- Vitest
- Tailwind CSS 4 и обычный CSS

## Локальный запуск

```bash
npm install
npm run dev
```

Основные страницы:

- `http://localhost:3000` — создать игру или войти;
- `/join` — вход участника;
- `/host/<secret>` — панель ведущего, создаётся автоматически;
- `/room/<CODE>` — интерфейс участника.

## Подключение нового Supabase-проекта

### 1. Создайте проект

Создайте пустой проект на [supabase.com](https://supabase.com). Старую прототипную схему применять не нужно.

### 2. Выполните миграцию

Откройте **SQL Editor → New query**, вставьте содержимое:

```text
supabase/migrations/202609160001_secure_quiz_mvp.sql
```

и выполните запрос. `supabase/schema.sql` содержит только указатель на каноническую миграцию.

Для проекта, на котором основная миграция уже установлена, дополнительно один раз выполните:

```text
supabase/patch_reliability.sql
supabase/patch_stats.sql
```

Patch добавляет безопасный автоматический reveal по дедлайну, агрегат `answered_count` и cumulative `participant_stats`, не раскрывая публичному клиенту host snapshot или распределение ответов до reveal.

Если предыдущая попытка миграции завершилась посередине и повторный запуск сообщает, что таблица или тип уже существует, сначала выполните `supabase/reset_failed_install.sql`. Этот cleanup предназначен только для нового проекта и удаляет все данные квиза. После него повторно выполните основную миграцию.

Миграция явно вызывает функции `pgcrypto` через схему `extensions`, как принято в Supabase.

- создаёт закрытые таблицы `rooms`, `questions`, `participants`, `answers`;
- хранит только SHA-256 хеши секретов;
- запрещает прямой доступ к игровым таблицам;
- открывает только узкие `security definer` RPC;
- публикует в Realtime только безопасный `room_signals`;
- не отдаёт игроку правильный ответ и чужие голоса до reveal.

### 3. Добавьте ключи

В Supabase откройте **Project Settings → API**. Скопируйте URL и anon key.

```bash
cp .env.example .env.local
```

Заполните:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_ANON_KEY
```

Anon key по модели Supabase является публичным browser credential. Безопасность обеспечивается закрытыми таблицами, RLS и RPC. Service role key приложению не требуется и не должен попадать в браузер.

### 4. Перезапустите стенд

```bash
npm run dev
```

Переменные окружения Next.js считываются при запуске, поэтому после изменения `.env.local` сервер нужно перезапустить.

## Smoke-test двух клиентов

1. Откройте главную и нажмите **«Я ведущий»**.
2. Дождитесь перенаправления на секретную `/host/<secret>` ссылку.
3. Скопируйте шестизначный код комнаты из панели ведущего.
4. В другом браузере или приватном окне откройте `/join`.
5. Введите имя и код комнаты.
6. Запустите вопрос ведущим — участник должен увидеть его автоматически.
7. Проверьте паузу и продолжение таймера.
8. Отправьте ответ игроком; повторное голосование должно быть заблокировано.
9. Выполните reveal: игрок увидит правильный вариант и реальные имена по вариантам.
10. Перезагрузите страницу игрока — сессия и ответ должны восстановиться.
11. Перейдите к следующему вопросу и завершите игру.

## Безопасность и архитектура

Клиенты не читают игровые таблицы напрямую. Все операции проходят через RPC:

- `create_room`
- `get_host_snapshot`, `save_questions`
- `join_room`, `get_player_snapshot`, `submit_answer`
- `start_question`, `pause_question`, `resume_question`
- `reveal_question`, `advance_question`, `finish_game`, `reset_game`

Realtime используется только как сигнал изменения версии. После сигнала ведущий и игрок заново получают snapshot со своими полномочиями. Это не позволяет Realtime-подписке раскрыть host hash, правильные ответы или ранние голоса.

Ведущий получает высокоэнтропийный секрет в URL; база хранит только его хеш. Участник получает отдельный секрет, который хранится в `localStorage` отдельно для каждой комнаты.

## Вопросы

Каноническая UI-модель:

```ts
type QuizQuestion = {
  id: string;
  fact: string;
  options: string[];
  correctIndex: number;
  durationSeconds: number;
};
```

Mapper репозитория преобразует её в snake_case DTO базы. Не используйте database DTO непосредственно в UI.

Исходный набор из 10 вопросов находится в `lib/questions.ts`. LocalStorage `fact-quiz:questions:v2:<token>` может использоваться как локальный черновик, но серверный snapshot является источником истины online-комнаты.

## Ограничения MVP

- комнаты истекают через 7 дней;
- нет отдельной учётной записи пользователя;
- секретная host-ссылка даёт права ведущего — её нельзя публиковать;
- нет CAPTCHA/rate limit на создание комнат;
- автоматическая очистка истёкших комнат пока не настроена;
- SQL миграция рассчитана на новый пустой Supabase-проект.
