# AGENTS.md

## Назначение проекта

Это Next.js-приложение командного квиза «Угадай, про кого этот факт». Ведущий управляет вопросами и таймером, участник выбирает один вариант, после раскрытия имена проголосовавших группируются по вариантам.

Рабочая директория проекта — папка `quiz`. Все команды выполняйте из неё.

## Обязательный контекст перед изменениями

Проект пока является локальным MVP, а не готовой многопользовательской системой.

- Панель ведущего хранит локальный черновик вопросов в `localStorage`, но online-комната использует Supabase snapshot как источник истины.
- В `lib/questions.ts` зафиксированы 10 исходных вопросов. Не заменяйте их демонстрационными данными.
- Текущая версия ключа черновика: `fact-quiz:questions:v2:<token>`.
- URL ведущего содержит высокоэнтропийный секрет; база хранит только SHA-256 хеш.
- Экран ведущего и игрока используют RPC snapshots и безопасные Realtime-сигналы.
- Правильный ответ и чужие голоса не должны попадать в player snapshot до `reveal`.
- Без настроенных env online-маршруты должны показывать `SupabaseSetup`, а не имитировать синхронизацию.
- `supabase/migrations/202609160001_secure_quiz_mvp.sql` — каноническая схема для нового пустого проекта.

Не сообщайте, что realtime, комнаты или защита ведущего работают, пока они действительно не подключены и не проверены.

## Технологический стек

- Next.js 16 с App Router
- React 19
- TypeScript в strict mode
- Zod для доменной валидации
- Vitest для unit-тестов
- Tailwind CSS 4 импортирован, основная визуальная система находится в `app/globals.css`

## Ключевые файлы

- `app/page.tsx` — главная страница и CSS 3D-иллюстрация квиза.
- `app/join/page.tsx` — ввод имени и кода комнаты; пока не проверяет существование комнаты.
- `app/room/[code]/page.tsx` — экран участника; сейчас демо, не синхронизирован с редактором.
- `app/host/[token]/page.tsx` — orchestration редактора и режима проведения, таймер и локальная загрузка.
- `components/QuestionEditor.tsx` — контролируемый редактор вопросов; не должен напрямую работать с хранилищем.
- `components/VoteGroups.tsx` — представление голосов, сгруппированных по вариантам.
- `lib/questions.ts` — канонический тип вопроса, Zod-схема, 10 исходных вопросов и storage adapter.
- `lib/votes.ts` — чистая группировка голосов.
- `lib/game.ts` — ранние утилиты состояний и таймера; перед расширением проверьте, используется ли модуль.
- `lib/supabase.ts` — nullable browser client при наличии env-переменных.
- `supabase/schema.sql` — предварительная, не production-ready схема.

## Инварианты модели вопросов

Используйте только каноническую клиентскую форму:

```ts
type QuizQuestion = {
  id: string;
  fact: string;
  options: string[];
  correctIndex: number;
  durationSeconds: number;
};
```

Соблюдайте ограничения:

- минимум один вопрос в наборе;
- факт после trim не пустой;
- 4–10 непустых вариантов;
- один `correctIndex` в границах массива;
- `durationSeconds` — целое число 5–300;
- ID вопроса стабилен при редактировании и перестановке;
- при удалении варианта корректно пересчитывается `correctIndex`;
- при перестановке вариантов правильность должна оставаться привязана к тексту варианта.

Для Supabase используйте явный mapper между `correctIndex`/`durationSeconds` и `correct_index`/`duration_seconds`; не распространяйте snake_case в UI-модель.

## Правила хранения вопросов

- `defaultQuestions` — сохранённый проектный набор из 10 вопросов и fallback.
- Не повышайте версию storage-ключа без необходимости миграции или намеренного сброса локальных черновиков.
- Не перезаписывайте валидный локальный набор при каждом mount.
- Считайте содержимое `localStorage` недоверенным: всегда валидируйте Zod-схемой.
- Ошибка чтения должна приводить к безопасному fallback; ошибка записи должна отображаться ведущему.
- При подключении Supabase заменяйте storage boundary/repository, а не переносите сетевые операции внутрь `QuestionEditor`.

## Состояния и таймер

Состояния проведения сейчас:

```text
lobby → running ⇄ paused → reveal → next/finished
```

Требования:

- интервал существует только в `running`;
- при паузе, смене режима и unmount интервал очищается;
- запуск проведения сбрасывает текущий вопрос на первый;
- редактор нельзя менять во время активного вопроса без явного сброса;
- последний reveal должен вести в `finished`, а не в неработающий next;
- после Supabase серверные timestamps и remaining time должны стать источником истины, а клиентский интервал — только отображением.

## Результаты голосования

Используйте группировку по вариантам через `groupVotes`/`VoteGroups`.

Обязательное отображение:

- каждый вариант присутствует даже при нуле голосов;
- под вариантом перечислены конкретные проголосовавшие;
- правильный вариант выделен и подписан «Правильный ответ»;
- при отсутствии голосов — «Никто не выбрал»;
- на экране участника допустима метка «Вы».

Не возвращайте столбцы «Итог»/«Результат» и персональные подписи «Правильно»/«Неверно»: это осознанно удалённое требование.

## Визуальная система

Сохраняйте текущий визуальный язык:

- глубокий зелёно-графитовый фон;
- изумрудный акцент `--emerald`;
- крупная контрастная типографика;
- округлые тёмные панели;
- CSS 3D-иллюстрация вопроса и вариантов на главной;
- desktop-first композиция ведущего и mobile-first доступность участника;
- видимый keyboard focus и достаточный контраст.

Не возвращайте старый лаймовый цвет и текст «01 / Игра на знание команды» над hero-заголовком. В правой hero-иллюстрации не нужен слоган или другой поясняющий текст.

Для новых сложных layout-блоков используйте CSS-классы в `app/globals.css`, а не увеличивайте объём inline-стилей.

## Доступность

- Все поля должны иметь доступные подписи.
- Выбор правильного ответа — настоящая radio group.
- Disabled-состояния должны быть семантическими, не только визуальными.
- Кнопки-иконки должны иметь `aria-label`.
- Ошибки сохранения/валидации должны быть читаемыми и, где уместно, иметь `role="alert"`.
- Не используйте цвет как единственный способ обозначить правильный вариант.

## Supabase: требования следующего этапа

Перед подключением production backend:

1. Пересмотреть `supabase/schema.sql`; повторное создание enum/publication сейчас может быть неидемпотентным.
2. Не выполнять текущий SQL в production без аудита RLS.
3. Не разрешать публичные произвольные update/delete комнаты и вопросов.
4. Не хранить или отдавать `host_token` через публичный participant query.
5. Реализовать серверное создание комнаты и криптографически стойкий токен ведущего.
6. Ограничить один ответ уникальностью `(question_id, participant_id)` и серверно проверять принадлежность комнате.
7. Разрешать чтение ответов участникам только в reveal, если этого требует продуктовая модель.
8. Обеспечить идемпотентное восстановление участника по room + session ID.
9. Удалить все demo votes после подключения реальных `answers`.
10. Добавить тесты двух клиентов/контекстов: ведущий и участник.

## Команды и обязательные проверки

```bash
npm test
npm run build
```

Обе команды должны проходить перед завершением задачи.

Текущее подтверждённое состояние:

- 2 test files passed;
- 6 tests passed;
- production build passed.

Скрипт `npm run lint` сейчас использует устаревший для Next.js 16 вызов `next lint`. Не считайте его рабочей проверкой, пока конфигурация ESLint не будет обновлена.

При изменении интерактивного UI дополнительно проверяйте через браузер:

- редактор загружает 10 вопросов на чистом `v2`-ключе;
- невалидный вопрос блокирует проведение;
- изменения переживают reload;
- запуск/пауза/продолжение таймера;
- reveal отображает группированные имена;
- desktop и мобильную ширину для затронутого экрана.

## Стиль реализации

- Следуйте существующему TypeScript/React стилю, но при существенной правке разбивайте длинные однострочные компоненты на читаемые функции и компоненты.
- Доменную логику держите в чистых функциях `lib/` и покрывайте unit-тестами.
- Компоненты форм должны оставаться controlled.
- Не добавляйте библиотеку drag-and-drop без явной необходимости; текущие кнопки вверх/вниз доступны с клавиатуры.
- Не добавляйте внешние графические ассеты для hero без продуктовой необходимости: текущая иллюстрация выполнена CSS.
- Не коммитьте `.env.local`, ключи Supabase, токены или реальные секреты.
- Не редактируйте `.next/` и `node_modules/` вручную.

## Definition of Done

Изменение считается завершённым, когда:

1. Поведение соответствует запросу и не нарушает перечисленные инварианты.
2. Пустые, ошибочные и мобильные состояния учтены для затронутой функции.
3. Добавлены или обновлены unit-тесты доменной логики.
4. `npm test` проходит.
5. `npm run build` проходит.
6. Для UI выполнена браузерная проверка основного сценария.
7. README обновлён, если изменились запуск, архитектура, переменные окружения или статус возможностей.
